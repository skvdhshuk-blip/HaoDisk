# 0.2.1：扫描达到上限后仍可审阅文件夹

## 问题与修复

扫描较大的工作目录达到 500,000 项上限后，0.2.0 用整次扫描的 `stoppedEarly` 阻止所有项目清理。因此，即使某个子目录早已完整读取，右键菜单和工具栏的清理入口仍是灰色。

0.2.1 移除了这个全局禁用条件。已经读取的普通文件与文件夹可以加入审阅；真正调用系统废纸篓前，继续检查授权边界、所有路径祖先的身份、项目身份。文件夹必须完整重扫，且项目数和每项文件身份均与原记录一致。只扫描了一部分、发生变化、无法读取或命中保护规则的文件夹仍不会移动。扫描上限未提高，沙箱权限未扩大。

扫描停止原因单独记录：手动停止显示“扫描已停止”，达到数量上限显示“已达扫描上限”。达到上限时提供“选择较小的文件夹”入口，默认定位当前目录；说明应选择待清理项目的较小上级目录。部分结果的审阅清单增加一次有针对性的复核说明。

## 回归证据

1. 新增测试先在旧代码失败，复现已完整扫描的目录被整次扫描状态阻止。
2. 对同一受限扫描中的两个目录分别测试：完整目录通过复核并到达注入的废纸篓操作；未完整读取的目录被拒绝，操作不被调用，文件保留。
3. 受限扫描中的已读取普通文件可通过身份检查；取消和数量上限仍不是完整扫描，且停止原因可区分。
4. 既有权限拒绝、保护路径、祖先被链接替换、文件 / 深层内容变化与废纸篓失败测试保持通过。
5. 对用户报告的真实构建目录执行只读扫描和完整身份复核，通过；验证过程注入无操作回调，没有删除该目录。

6. 本机开发签名沙箱 App 再次扫描原授权范围达到 500,000 项上限后，真实构建目录的右键“加入待清理”和工具栏入口可用；审阅显示 1 项及正确路径，移动按钮可用。取消审阅并移除了验证时加入的清单项，未执行移动。

验证结果：17 项 Swift Package 测试、18 项 Xcode XCTest 通过；Release 双架构构建和签名验证通过，交付包版本为 0.2.1 (3)。

本次只修复扫描状态对清理的过宽限制。授权根目录、系统路径、Library、应用资料包等既有保护保持不变。
