# HaoDisk 0.2.4 完整扫描与局部更新

## 行为与数据边界

| 能力 | 0.2.3 | 0.2.4 |
| --- | --- | --- |
| 扫描 | 全树数组，到 500,000 节点停止 | 系统目录流式枚举，SQLite 临时索引，无节点数量上限 |
| 完整性 | 全局停止原因，部分目录仍显示确定容量 | 每个目录保存未扫描／扫描中／完整／部分读取状态并向祖先传播 |
| 隐藏元数据 | Foundation 自动跳过 `._` 文件 | 包括 `._` 文件，和普通隐藏文件一起统计、复核 |
| 列表 | 排序后保留全部直接子项 ID | 后台 SQL 排序，512 行分页及相邻页预取 |
| 缓存 | 16 个目录、500,000 行上限 | 保留总预算，每目录进一步限制为 8 页（4,096 行）；最近使用优先 |
| 清理成功 | 整个授权目录重新扫描，节点 ID 重分配 | 事务删除成功目标，汇总受影响祖先，节点 ID 稳定，刷新受影响目录 |
| 外部变化 | 重新扫描 | 仍由手动重新扫描同步；移动前必须复核 |

SQLite 索引是唯一的扫描事实源。`DiskSnapshot` 只保存会话和根目录摘要；`DirectoryPresentation` 保存当前目录、祖先、有限页面和最多 80 块＋汇总入口。界面不通过节点 ID 同步读数据库。后台 `DirectoryCache` 准备展示数据，索引访问锁串行化数据库查询、扫描写入与清理事务。

缓存键包括扫描会话、目录 ID、目录修订号、统计方式和排序方式。选择和悬停不会重新排序；列表只在数据版本或加载页变化时更新，清单标记只更新可见行。新目录请求取消旧请求，SQLite 排序支持中断，过期数据不能覆盖当前页面。

清理仍先检查授权路径、文件身份和文件夹全部直接／递归内容，再调用系统移到废纸篓。只有成功项目进入索引更新；硬链接计量归属转给剩余链接。更新父目录身份后，允许继续清理刚删过子项的父文件夹；额外外部变化仍会拒绝。索引写入失败会保留真实移动结果并锁住后续清理，要求手动重新扫描。

索引目录位于应用沙箱的 `Library/Caches/HaoDisk/ScanIndexes`，仅服务当前会话。旧索引在后台关闭和移除，避免切换目录或重扫时主线程执行数据库关闭与磁盘清理；正常退出清理，后续启动清理已退出进程的残留。没有跨启动复用或文件监听。

## 回归与原生验收

- 核心回归包含读取不完整、取消、隐藏文件、AppleDouble、权限不足、保护路径／应用包、稀疏文件、硬链接和自然名称排序。
- 索引回归包含分页边界与淘汰、会话替换、统计方式切换、过期请求、路径恢复、子项再父目录清理、硬链接转移、部分失败、SQLite 只读故障后的禁止重复移动以及索引生命周期。
- 实际 SQLite 故障使用 `PRAGMA query_only=ON` 制造，文件系统移动使用隔离 fixture；不会删除用户工作区内容。
- 签名沙箱应用中，`Incremental-024-QA/Disposable/child.txt` 移到废纸篓后，父目录从 37 KB 更新为 25 KB；随后 Disposable 文件夹成功移到废纸篓，根目录从 27 项变为 26 项。未清空废纸篓。
- 最终交付构建中，`FinalCleanup/._metadata` 正确显示并计入容量；包含该文件的 FinalCleanup 文件夹成功移到废纸篓，未触发根目录重扫。正常退出后，原会话索引目录已消失。
- 12,000 个实际文件目录扫描完整，跳到约第 9,600 行并连续滚动后仍正确加载名称与容量；右键加入清单保持滚动位置。
- 最小和默认窗口、深浅色下验证磁盘容量、长中文名称、极小方块。容量无法放入的块保持真实面积，悬停入口仍保留。
- 工作区扫描取消后显示 97 个根级项目及“已读”状态；重新扫描替换会话。最终完整扫描结果另见下方实测记录。

滚动条 `setValue` 的一次 CUA 调用超时；随后采样显示应用主线程在等待事件，物理占用 130.9 MB，重新连接后可见约第 9,600 行，普通连续滚动成功。该自动化调用时间不作为应用响应耗时。

## 性能测量口径

`performance-benchmark.swift` 使用真实 SQLite、相同命名与大小分布的 12,000／100,000／600,001 个直接子项；统计首次目录准备、缓存命中、分页、选择逻辑、SQL 查询数和布局复用次数。旧版本基线从本地 `10825dd` 提取，使用相同 12,000／100,000 子项分布。

所有毫秒指标均为内部逻辑耗时。没有把工具调用时间或内部函数耗时当作鼠标输入到屏幕呈现的延迟；端到端 P95 50 ms／100 ms 目标尚未独立测得。原生交互已做功能检查，纯悬停的端到端延迟未单独量化。

首次自然名称排序需要处理整个目录，仍可能耗时；该操作在后台进行，完成后按页读取。缓存命中和选择无需重复排序。这里主要改善完整性、浏览时内存和清理后的更新成本，不承诺首次全量扫描比旧版提前截断更快。

## 构建与回滚

交付为 macOS 14+、arm64 / x86_64 通用应用，Apple Development 签名和原有三项沙箱 entitlement。当前是本地测试包，未公证、未提交 App Store、未推送 GitHub。制品哈希与源码提交记录在同目录的 0.2.4 build JSON；之前的 0.2.3 ZIP 保留，可回退应用程序。临时索引无需数据库迁移，授权书签沿用既有格式。
